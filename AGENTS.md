# AGENTS.md — working guide for Codex & Claude Code

Read this and `ARCHITECTURE.md` before touching the repo. They exist to save
tokens and prevent rework: the conventions below are the accumulated "house
rules" for this project. Follow them so every change ships the same way.

## The standing process (one feature = one PR)

1. **Implement** the change on branch `claude/value-stock-screener-idr6nm`
   (create from latest `main` if needed). One discrete feature per PR.
2. **Bump the version** in **both** `stock_comber/__init__.py` and
   `pyproject.toml` (SemVer; docs-/frontend-only changes are patch bumps).
3. **Update the changelog + release notes:** add an entry to `CHANGELOG.md` and
   `docs/RELEASE_NOTES.md` (Keep a Changelog format; newest on top; add the
   version-tag link line).
4. **Test:** `python -m pytest -q` must pass. Add tests for new behavior. For
   frontend changes, verify with Playwright (route-stub the APIs, assert DOM and
   a zero `pageerror` count).
5. **Commit** with a clear message and the attribution footer (below).
6. **Push** with `git push -u origin <branch>` (force-with-lease is fine when the
   branch only carries already-merged history — see "Rebasing" below). Retry
   network failures with backoff (2s, 4s, 8s, 16s).
7. **Open a PR** *only when explicitly asked* — via `mcp__github__create_pull_request`.
   Then `subscribe_pr_activity` and drive CI (tests on 3.9/3.11/3.12) + the Vercel
   preview to green before squash-merging; `unsubscribe` after merge.
8. Treat routine post-merge PR-lifecycle notifications as no-ops.

## Hard constraints — do not violate
- **Stay at ≤ 12 serverless functions.** Never add a 13th `api/*.py`. Reuse an
  endpoint with a query param, or add a library module under `stock_comber/`.
  (See ARCHITECTURE.md → "The 12-function cap".)
- **Secrets are write-only.** API keys and `DATABASE_URL` live in env/DB and are
  **never** returned to the browser or logged. The audit log stores only SHA-256
  key *fingerprints*, never raw keys.
- **No model identifiers in repo artifacts.** Never put the serving model name /
  ID in commits, PR titles/bodies, code comments, or any pushed file. Chat only.
- **Repo scope:** work only within `bobs-dev-attic/stock-comber`.
- **Never** push to a branch other than the designated one without explicit
  permission. Don't open a PR unless the user asks.

## Rebasing onto a squashed main
PRs are squash-merged, so after a merge your local branch's pre-squash commit
diverges from `main`. To start the next change cleanly:
```
git fetch origin main            # retry with backoff on proxy 5xx
git checkout -B claude/value-stock-screener-idr6nm origin/main
```
If a merge conflict appears on an open PR, **merge base into the branch** (never
rebase/force-push someone else's history); regenerate lockfiles/generated files
with tooling, never by hand; re-test; push.

## Gotchas learned the hard way
- The dev proxy **blocks Yahoo/Google/Finnhub** — you cannot test live fetches
  locally. Stub them; trust hosted CI + Vercel preview for real upstream calls.
- **CSS `[hidden]` can be overridden** by an author `display:` rule. When hiding
  an element by attribute, also assert computed `display:none` (a past banner bug:
  `.banner{display:flex}` beat `[hidden]`; fixed with `.banner[hidden]{display:none}`).
- `should_run_now` expects `{"schedule": {...}}`, not a bare schedule dict.
- Keep the three theme palettes in sync (`:root`, the `prefers-color-scheme`
  block, and `:root[data-theme="dark"]`).
- Prefer `datetime.now(timezone.utc)` over the deprecated `datetime.utcnow()`.
